## 非阻塞迁移影响

共享 verifier 接入运行时后，旧的、没有聊天来源版本标记的 contextual Iris 回复
会被过滤，即使当时 scope 为空/撤销或目标群不参与共享。这是保守来源迁移行为，
不是旧群消息被删除；新产生的有标记回复仍可复用，闲聊不受影响。
独立审查将旧同群回复过渡期体验列为 P2 后续，不为恢复旧回答而放开不明来源。

## 发布与撤回操作边界

遵循[试点重启顺序](../../deploy/pilot/README.md#planned-restart-and-reactivation)：精确SHA的CI通过后，
从该提交Git归档构建镜像；新鲜核对生产版本、三群名单、能力哈希、队列和就绪，持久化关闭全局、
停止Caddy，生成加密Postgres/Redis配对备份，再应用`0058_shared_working_chat.sql`和部署。

内部Bearer保护的`GET /internal/working-chat-scope`在首次迁移后应为空；只有显式
`PUT`的`expectedVersion/state/groups/updatedBy`四字段允许变更，群集合使用设计中的精确三群。
不能从机器人自动入群推导共享权限，也不能用请求问题里的群名扩大集合。
仍停公开入口时恢复私网问答并验证实模内部草稿，全部通过后才恢复入口。

失败先关闭全局和入口，按当前scope版本CAS撤销共享；409须核对在途发送，不强拆记录。
在撤销已确认、基础问答安全且私网健康门禁通过后恢复原有限问答，必要时回退精确旧镜像。
本次是加法迁移，不能为了回退镜像直接覆盖生产数据库新事实。
内部草稿、内存改写、真实回执集成与飞书投递分别记录，不伪造群成员动作或回调。
