已观察到的验证边界：未配置 scope 时不跨群，明确“只看本群”不带入外群正文或
带外群来源的 Iris 旧回答；指定参与群可收窄来源；普通闲聊不触发共享查询。
这些属于本机受控测试，不代表生产已经启用。

独立审查还发现旧消息处理器在生成普通回答期间持有 incoming-message 锁，
双群同时提问且互为证据时可能形成跨调用等待。当前随发送链路一起修复：
普通 receipt-backed 回答在模型/远端核验前释放外层锁，准备/发送阶段统一按
scope、runtime、全部消息 ID 排序、delivery 的顺序重新核验。旧直接命令路径的
保护不在本次扩大重构；真实并发数据库测试通过前，不声明该问题已修复。

本机 Docker Desktop 隐藏启动后在既有 dockerInference socket 初始化处失败；
未重置或删除 Docker 数据。真实 PG 结果须由隔离数据库或精确提交的 CI 补齐。

## 非阻塞迁移影响

共享 verifier 接入运行时后，旧的、没有聊天来源版本标记的 contextual Iris 回复
会被过滤，即使当时 scope 为空/撤销或目标群不参与共享。这是保守来源迁移行为，
不是旧群消息被删除；新产生的有标记回复仍可复用，闲聊不受影响。
独立审查将旧同群回复过渡期体验列为 P2 后续，不为恢复旧回答而放开不明来源。
