## 问题与职责选择

[上一受限窗口](iris-opinion-withdrawal-20261008.md)的正例初判识别了问题，但生成和唯一
修正都漏抄“现在就向”中的“就”，因此严格绑定拒绝，未进入语义审核。拒绝本身正确；
需要改变的是把“选择依据”和“逐字复制依据”一起交给模型的职责。该失败不能归因于
新增撤回出口，也不能通过模糊匹配补字或再次强调逐字抄写来宣称修复。

有限设计：程序按完整、当前授权evidence生成中性词法单位目录，保留全部字符、空白和
标点。dependency/inference计划只选择sourceRef和连续首尾单位ID；程序从原始字符串
取回完整引用。目录没有正确答案、人工前提/结论标签或候选审核结论，不替代完整来源。
拒绝越界、反向、未知来源、歧义来源、空白或超过原引文长度上限的选择，不允许自由quote
回退、跨源拼接或非连续省略；verificationTarget仍须位于所选前提或决定内。

目录在一次render内冻结，初次生成、绑定修正和审核后修正使用相同目录。来源原文和
真实历史仍完整提供；最终审核看到程序取回的原文及实际编译文案。计算quantity合同、
no_intervention撤回、一次总修正预算、审核和发送前边界保持。词法目录只解决定位，
不证明选择的业务角色、先后关系或介入价值正确，不把ID当业务数字。

原始单位和resolvedSourcePlan保留原字符串；后续通用发言校验既有的NFC规范化保持，
本修复不改变共享文本校验，也不声称最终发言的Unicode字节与来源完全相同。

## 预先冻结的退出条件

本地先验证真实漏字复现、连续范围取文、非法位置拒绝、Unicode/标点/空白保真、三处
撤回与单次修正、完整审核接线和legacy/计算不变，再运行Core、类型检查、构建及CLI。
历史模型原件不修改；归档回放如适配新请求协议，须明确列出适配范围并保留原业务预期。

合成测试沿用上次四条完整输入、顺序和预期，从实际assess开始，没有人工中途替换响应：

| 案例 | 冻结的产品要求 |
| --- | --- |
| order-wait | 明确版本完成后再落实，应无意见，不能虚构绕过条件。 |
| order-bypass | 尚未验收却立即向客户作确定承诺，应指出依据缺口，提出具体、可理解的验证或条件承诺建议。 |
| permission-wait | 明确等授权确认后再开放，应无意见。 |
| permission-bypass | 授权尚未确认却现在开放，应建议先确认范围和条件，不编造法律结论或确定后果。 |

正例只得到空稿、technical_error或审核拒绝都不算通过；复述已知状态而没有实际帮助的
建议也不算通过。负例初判skip不证明使用了新增撤回出口。四例全部通过也只代表此有限
合成范围，不覆盖历史算术、过度确定、重复介入或真实飞书完整能力。

精确应用提交、源码、runner、启动器、四例输入和上下文先冻结哈希。最多24次HTTP、
reported tokens达到100000后禁止下次调用、45分钟一次窗口；逐HTTP核对精确型号免费
额度至少200000、未来有效期、用完即停已开启。无付费回退、自动HTTP重试、重启重采。
首次技术或语义失败立即停止，保留未调用案例和失败原件，不追加同类prompt变体。
