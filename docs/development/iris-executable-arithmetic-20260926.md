## 独立审视与本次取舍

检查当前实际代码及[不可改写原文实验](iris-immutable-review-20260926.md)后确认：
模型复核同时负责问题身份、事实支持、算术、推断强度、必要数字、重复判断及引文。
本地校验只约束结构、引文和连续性，原本没有执行计算；因此只要模型把错误句
解释成合理意思，明确的 `16−10=−6` 仍可通过。模型能力、上下文长度和职责干扰的
因果贡献仍未分离。本次不以重复实验或模型切换代替根因证明。

候选与真实历史已在输入中分开；没有证据证明这个输入修复同时解决了语义重复。
原验收要求来源支持、直接算术正确、风险恰当限定和避免重复，符合白皮书及产品
目标，本次不修改原场景预期、不把整体 false 当目标错误已识别。

选择在既有链路增加明确算式的程序矛盾检查，而不是增加模型提取/判定轮次。
更广的“自然语言→结构化断言→事实审核”仍未证明忠实性，本次不实现该新架构；
单纯增加审核字段/原文引用已经失败，本次也不重复。

## 实现及严格能力边界

- [arithmetic.ts](../../apps/core/src/proactive-discussion/arithmetic.ts)直接从候选原文读取
  明确二元算式和“减去…，差额为…”等表达，保留 UTF-16 位置、原句、运算符及
  有符号操作数，用 BigInt 有理数计算，避免浮点误差；不使用模型提取结果或 eval。
- 支持有限十进制、显式加减乘除、同量纲加减及明确金额单位缩放；不推断业务
  口径、隐含数量、未写出的运算或公司事实。数值相等只是算式一致，不能证明事实。
- 含引用、否定、纠错、假设以及复杂连算/括号/科学计数的表达保留给语义审核；
  未识别不等于通过计算验证。句级保守排除会造成漏检，不宣称通用中文数学理解。
- [review-receipts.ts](../../apps/core/src/proactive-discussion/review-receipts.ts)在原模型
  判断之外检查 draft 和存续 assessment 的描述、观察、理由、建议、变化说明。
  原模型字段判定保留，已发现的算术矛盾追加到有界本地诊断；不能被模型 true 覆盖。
- [model.ts](../../apps/core/src/proactive-discussion/model.ts)在初审与终审传入当次
  assessment。初审矛盾进入原有唯一一次成对修正；终审仍错返回 null。
  [评估脚本](../../scripts/pilot/proactive-discussion-eval.ts)使用同一当前 pair 核验，
  避免 trace 仍把运行时拒绝记为本地通过。原 trace 的 `receipt_invalid` 是历史通用
  本地复核失败标签，不专指算术或语义归因。

这关闭明确语法覆盖范围内“错误计算获模型批准即被返回”的程序缺口；不关闭
无依据数字、风险后果过度确定、自然语言遗漏计算及重复意见等整个能力缺陷。

总窗口20分钟、最多23次HTTP、80000 reported tokens发起下次前停止阈值；不是绝对

或付费回退。独立审查修正了quota等待后未复核总截止时间的边界，再启动窗口。

首例只回放原归档的生成pair，实时执行审核→原有一次修正→终审；不能称首例是
新鲜生成。之后依次为原目录的 arithmetic、inference、qualified-risk、paraphrase，
各一轮实际 assess/render。每例须保留正确判断、完整有效意见、全部存续文本正确，
无依据确定后果不能通过；首例还必须真正改正负号而不是只改uncertainty。
每例结果由主代理阅读原文作独立语义判断后才允许下一例。首个执行或语义失败停止，
不重采、不修改预期、不继续prompt变体。即使五例通过也不替代完整15×2及真实群验收。
