# Iris 试点共享工作群聊设计

日期：2026-09-09。状态：用户已确认产品范围；实现与验收进行中，尚未部署或开启。

## 1. 已确认的用户体验

在同一显式共享范围内，成员正常发出的文字讨论自动成为 Iris 可查阅的工作上下文。在另一个参与群 @Iris，可以查询、比较和讨论这些内容；不需要先说“保存到知识库”，不逐条审批。目标群全体成员可以通过 Iris 获取共享范围内的讨论，不要求提问者也属于每个来源群。

这是“工作讨论共享”，不是“正式知识发布”。讨论必须按来源群和时间归属，提议不能自动升级成现行公司事实。Wiki 写入、任务执行、主动广播、原始语义记忆/线程/行动项的跨群投影仍不由此开启。既有单文档授权设计保持独立。

## 2. 选择与边界

采用持久化、精确群 ID、可撤销的共享范围，而不是开放机器人加入的所有群，也不是继续要求每条消息先发布为 Wiki。复用既有消息接收、按 ID 新鲜读取和问答链路；本轮不重建全量语义记忆系统。

## 3. 持久化契约

`working_chat_scopes` 保存 scope ID、正整数版本、active/revoked 状态、2–5 个唯一群 ID/显示名、操作者和更新时间。没有记录时默认关闭。修改采用 expectedVersion CAS；任何成员或状态变化递增版本，移除后重新加入不能复活旧答案。服务端内部管理 API 负责显式范围变更，问答请求不接受额外允许群列表。

对外群原文及其派生回答保存独立 `SharedChatSourceBinding`：scopeId、scopeVersion、sourceChatId、destinationChatId、messageId、contentHash。Hash 基于新鲜人类原文，时间/群标签不混入正文 hash。所有进入模型的外群消息都必须记录，不只记录被引用的消息。父消息、标签同样记录。

原始来源集合随 `underlyingChatSources` 穿过 Iris 历史回复复用与多轮改写，不能洗成“没有来源的助手回答”。本群原有文档来源链保持不变；共享验证器接入运行时后，无法确认 provenance 的旧 contextual 回复不复用，即使 scope 尚未激活或目标群不在 scope 也采取此保守迁移规则。新生成、明确记录空聊天来源的本群回复仍可复用；闲聊路由不受影响。旧回复过渡期的可用性优化为非阻塞后续，不能靠信任不明来源来恢复。

## 4. 查阅与生成

- 保留 standalone 闲聊先分流、零资料加载。
- contextual 从服务器解析发问群所在 scope；目标与来源群均须当前启用、允许读群上下文，目标须允许 @回复，Iris 须仍能访问两群。
- 当前发问群的人类消息提供“昨天/旧版/刚才”的对话锚。跨群主题候选仅在允许群内查找；SQL 返回消息身份而非作为权威正文。
- 外群来源无日期但有主题时默认查最近 30 天的候选；本群已有近期/日期召回不在此重构，显式日期沿用有界日期召回。无主题跨群回顾（如“其他群最近聊了什么”）读取被点名且属于范围的来源群，或未点名时其他参与群，每个外群最多20条近期消息，再按时间与全局20/10预算选择；不进行全库扫描。查询窗口不等于物理保留周期，不宣称无限历史或回调全量补录。
- 通过既有 Feishu reader 按来源群、精确 ID 重新读取正文；拒绝、缺失、删除或错误不回退旧数据库正文。实时读取源群失败时不得把其旧内容注入模型。
- 跨群合计保留既有限额：20 条 prompt、10 条规划证据、8,000 字/条、24,000 字原文总预算、最多 8 个历史候选和 8 个单跳父/根。不是每群分配一整套后拼接。
- 来源群、时间、消息 ID 贯穿去重、主题窗口、Cn 证据与 XML。相邻“这是旧版”等标签必须与正文属于同一个来源群，不能因同一发言者在不同群交错发言而误绑定。
- 生成前重验共享范围与所暴露消息；中文自然回答，并区分“该群当时讨论”与“已确认制度”。未知来源或无证据时说明边界，不声称必须先写知识库。

## 5. 撤销、发送与连续对话

同一个验证器用于模型输入、旧 Iris 回答复用和最终发送：精确 scope 版本、持久化 runtime、机器人访问、精确新鲜消息正文 hash、本地 tombstone。Reader 单次上限 8 条，必须分批完整核验。

独立 `answer_reply_chat_source_traces` 绑定发送回执，参与幂等语义指纹及回执不变式。Scope 变化与 `beginAnswerSend` 使用共同事务锁；先锁 scope，再 runtime，再对来源及 incoming 消息的统一去重集合按稳定排序加锁，最后 delivery。普通 receipt-backed 回答在模型生成与远端核验期间不持有外层消息事务；旧直接命令路径保留既有保护，不把本次局部改动说成全局事务重构。删除路径复用消息锁。

授权线性化点是 `send_started`。撤销先完成则旧 prepared 回答不得发送；若原答案已开始外部发送或待对账，范围变更应返回明确冲突，不能谎称已撤回在途请求。删除同理。紧急全局关闭仍保留，已发出的外部请求无法撤回。

已可观测的消息删除/修改、来源群或目标群停用、机器人失权、范围版本变化都使原答案及其改写链失效；不得在重试中自动换成新版本认可旧正文。Scope、durable runtime、本地 tombstone 使用本地事务边界；飞书正文与访问性使用发送前最新成功验证，两者不是分布式原子事务，不能声称阻止最后远端探针之后尚不可观测的编辑。安全提示沿用发送状态机，不制造假发送/回调。

## 6. 有限验收与停止条件

完成标准是以下闭环均通过，而不是无限扩展防御：

1. A 群普通消息，不存 Wiki；B 群可查询、比较并给出有依据分析。
2. 范围外 C 群、未知群、停用群、失权来源没有正文进入提示词或答案。
3. 两群长文和标签正确归属，主题/日期查阅及中文连续两次改写正常。
4. prepared 后撤销、删除、改文、移除再加入均零原答案发送；超过 8 条消息完整核验。
5. 并发发送/撤销/删除与多轮来源链通过真实 Postgres 集成；无文档的聊天回复也可被权限阻断。
6. 闲聊零检索、现有本群问答/单文档共享回归不变；Wiki 写入、主动发言、任务执行保持关闭。
7. 精确提交 CI、受控部署、内部真实模型草稿验收分别记录，真实飞书投递另列，不能互相冒充。

P0/P1 阻塞解决后进入实际试用；文案/更长历史/更复杂消歧等非阻塞项进入待办。任何门禁未通过，不开启共享范围，保留当前基础问答。
