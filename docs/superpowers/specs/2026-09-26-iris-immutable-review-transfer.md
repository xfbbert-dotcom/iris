# 不可改写原文审核：有边界迁移验证

日期：2026-09-26。当前仅为可丢弃的合成诊断设计，不是产品审核架构批准或部署许可。

## 问题与已有证据

应用 `04aa3a09` 的六字段复核曾将候选里的 `16−10=−6` 理解成正确算术，
并批准没有来源支撑的确定交付后果。固定 Qwen3.8-Max 模型对照仍重现，见
[记录](../../development/iris-qwen38-review-20260926.md)。

随后固定原句 ID 的手工三选项关系 probe 在第一组正确区分算术方向和负号；
第二组正确拒绝过强后果，却把“尚无依据”误标为“明确矛盾”，按预先冻结的
三分类 oracle 停止：2 次 HTTP200，1409 reported tokens，后两组未调用。
该失败不改判；人工正确选项可能帮助模型识别错误，不能直接推断产品可用。

## 选择与非目标

本次只验证一项迁移：移除人工正确选项，程序从真实归档候选中机械列出全部
原文片段，要求逐片段审核。保留既有六项整体语义检查、数字凭据与建议凭据。
不增加生成或修正次数，不改生产模型，不实现任何群发或能力开关。

曾考虑仅执行数字表达式校验，以及让模型构造反例世界。前者仍需证明从自然语言
提取的表达式与业务口径忠实，无法单独解决过度确定；后者仍依赖模型发现漏项。
选择原文片段是因为它直接约束已观察到的“审核改写了被审核句”问题，同时可以
在已有固定输入上检验。不声称它能机械证明语言事实正确。

## 原文覆盖和审核约束

- 字段：新问题 `issueRef.description`、`observation`、`reasoning`、`suggestion`、
  `materialChange.explanation`、`draft.text`；existing issue ID 不作为新描述。
- 按中文句末 `。！？` 或换行机械分段，不按逗号拆散条件、否定和谓语。
  每段包含字段路径、UTF-16 起止偏移、原样文本与 SHA256。所有字符连续完整覆盖，
  不删句、不归一化、不增加“正确替代句”。这不是语义原子化。
- 完整所属字段、原始 evidence、身份与真实 discussion 仍可见，避免断章取义。
  片段和材料都不是系统指令；discussion 不扩大事实授权范围。
- 每个固定 ID 必须恰好一次返回 supported 和简短具体理由；缺项、重复、未知 ID
  或覆盖失败均失败。最多 64 个片段，超限在任何 HTTP 前退出。
- 建议、谨慎推断、来源允许的直接算术无需原文逐字陈述；不能靠一律拒绝通过。
  片段全部支持不能覆盖六字段、同一问题、重复/已处理或数字完整性的否定。
- 接受条件是既有本地审核通过 **且** 全部片段支持。不是把“矛盾/未知”混淆算正确；
  本迁移只使用产品已有的支持/不支持二值语义，独立复核仍检查理由是否正确。

## 固定实验与退出条件

冻结五份已有首次 review：old-negative-arithmetic、qualified-risk、paraphrase、
arithmetic、material-update。不生成或手工改写候选，不在 prompt 发送预期答案。
负算术对应原句必须被拒且说明负号/运算方向；两处过强条件后果必须各自在其原句被拒；
重复候选必须在 materialChange 和整体否定；两个正向候选仍须通过原校验器和所有
片段审核。仅因另一处错误拒绝不算目标修复。

使用已授权独立测试 key / qwen3.8-max，non-thinking，max_tokens 4096，
单请求 60 秒、总窗口 5 分钟、最多 5 次 HTTP、45000 reported tokens 请求前停止阈值、请求间隔
6 秒。每次窗口前核对精确型号免费额度及用完即停；无付费回退。首个 schema、
HTTP、固定布尔结果或覆盖失败停止，不重采、不修正；独立语义不通过也结束此候选。
reported tokens 是已返回的用量，最后一次响应可能越过停止阈值，不称绝对计费上限。
整个候选当前只允许这一轮迁移，不以继续堆提示词方式延长。

即使五份全部通过，仍只是首次审核的迁移可行性；缺少完整正确的条件风险正向
候选、修正后终审、端到端生成、15×2、真实群及部署验收。不能直接升级能力。
若失败，归档并结束本方案，本轮不再寻找第三个 prompt 变体；说明尚未修好的
具体原因和需要重新设计的边界，而非说在等明天或用户重复许可。
